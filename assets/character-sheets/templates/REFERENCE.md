# Character Sheet PDF Visual and Terminology Reference

This document is a durable text companion to the owner's character-sheet PDF templates in this directory.

It exists so future work can use the terminology, page structure, visual intent and D-0074 family distinctions without requiring the owner to re-upload the binary files in every chat or tool session.

## Source templates

- `Hoja de PJ - 5.0 - Simkin.pdf` — 5 pages / **Custom v1** source.
- `Hoja de PJ v2 - 5.0 - Simkin.pdf` — 5 pages / **Custom v2** source.

Both source PDFs remain the authoritative visual references. This Markdown file is an index/interpretation aid, not a replacement for them.

## Current D-0074 export-family interpretation

The approved visual families are:

1. Classic D&D-style — independently designed by the application;
2. Custom v1 — based on `Hoja de PJ - 5.0 - Simkin.pdf`;
3. Custom v2 — per Attribute — uses the first v2 main-page variant that groups skills beside Attributes;
4. Custom v2 — per Ability — uses the alternative v2 main-page variant with dedicated saving-throw and abilities/skills blocks.

The two v2 main pages are alternatives selected according to user comfort; they are not both mandatory pages in one ordinary export.

Each family receives its own design-specific Extended-page family. Extended pages are not one universal layout with a different color skin: typography, scale, spacing, borders, color and information organization should follow the selected base family as closely as practical.

Both owner custom designs include intentional PC portrait/image areas. They are part of the export mapping, not decorative space to ignore.

## Usage rule

Use these PDFs as reference for Spanish character-sheet terminology and for the owner's preferred information grouping/layout.

Do not silently replace a PDF label with an English product term merely because the implementation currently uses one. When the app and PDF terminology disagree, record the mismatch and reconcile it under the approved product/terminology workflow.

Likewise, do not infer that every field visible in a PDF must exist in every app screen or data model. Product/data decisions remain governed by the repository's approved decisions and conventions.

Do not silently correct spelling, rule-system assumptions, or possible inconsistencies found in the source PDFs. Preserve the source wording in this reference and flag any proposed correction separately for owner approval.

Under the current personal-use/non-publishing product scope, preserve the existing D&D branding/visual identity of these owner templates rather than spending implementation effort on rights-cleanup redesign. Revisit only if distribution scope later changes.

## Visual/page structure

### `Hoja de PJ - 5.0 - Simkin.pdf` / Custom v1

1. Main character sheet: identity/progression, armor/combat values, six attributes with saves/skills, compact spellcasting summary, attacks, and `Rasgos y Atributos`; includes the prominent PC portrait area.
2. Equipment sheet: `Equipo`, `Monedas`, `Gemas / Joyas / Arte`, and `Equipo Especial`.
3. Narrative sheet: `Trasfondo`, `Rasgos de Personalidad`, `Ideales`, `Vínculos`, `Defectos`, `Otros Rasgos y Atributos`, `Historia del Personaje`, and `Notas`.
4. Dedicated spell sheet: `Trucos` plus spell levels 1-9.
5. Notes sheet: large `Notas` area plus a large square grid.

### `Hoja de PJ v2 - 5.0 - Simkin.pdf` / Custom v2

1. Alternative main page A — compact main character sheet with skills grouped beside attributes, combat/attacks, `Rasgos y Atributos`, compact `Lanzamiento de Conjuros`, `Tesoro`, `Municiones`, and `Otros`; includes a PC portrait area.
2. Alternative main page B — main character sheet using dedicated `TIRADAS DE SALVACIÓN` and `HABILIDADES` lists while retaining the same overall combat/spell/wealth blocks; includes a PC portrait area.
3. Equipment/narrative sheet: `Equipo`, `Trasfondo`, `Vínculos`, `Ideales`, `Historia`, and `Equipo Especial`.
4. Dedicated spell sheet: `Trucos` plus spell levels 1-9.
5. Notes sheet: large `NOTAS` area plus a large square grid.

## D-0074 extension/overflow visual rules

When normal content does not fit after natural wrapping plus moderate font-size reduction/condensation above the hard readability floor:

- preserve the normal sheet's usability;
- leave a clear visual continuation cue in the originating section;
- continue only the overflow on the matching purpose-specific Extended page;
- preserve blank writable areas where practical;
- never silently discard/truncate data.

Custom Statistics mode 3 is the deliberate exception to ordinary continuation: when selected, custom statistics may be integrated elegantly into the normal/modified sheet **and** the complete Custom Statistics Extended page is still included.

Generated App Modified/Extended pages should remain recognizably part of the selected family even when geometry must change.

## Current QA terminology finding

### T-01 - `Quick Magic`

During Phase 4 owner phone QA, the installed app displays a section/settings terminology using `Quick Magic`.

The owner explicitly identified this as an inadequate Spanish-equivalent label and instructed that the PDFs be used as terminology reference.

The PDF source terminology for the corresponding spellcasting summary is `Lanzamiento de Conjuros`, with related labels such as `CD de Salvación de Conjuro`, `Modificador de Ataque Mágico`, `Aptitud Mágica`, `Espacios`, and `Espacios Gastados`.

Status: **open terminology reconciliation finding**. Do not silently rename during QA; record it for the post-QA correction/consolidation pass unless the owner explicitly asks to interrupt QA and fix it sooner.

## Future-agent continuity

When working on character-sheet UI or generated-sheet output:

1. Read `docs/decisions/D-0074_PC_SHEET_PDF_EXPORT_PRODUCT_DEFINITION.md`, this file and the directory `README.md` first.
2. Use the two PDFs themselves when binary/rendered access is available and visual fidelity matters.
3. Use this reference for terminology and page/grouping context when binary PDF access is unavailable.
4. Remember that v2 pages 1/2 are alternative main-page designs, not both mandatory pages.
5. Preserve portrait mapping, writable blank areas, readability floor and overflow cues under D-0074.
6. Record any newly discovered PDF/app mismatch here or in the appropriate QA/decision document.
7. Do not ask the owner to re-upload these PDFs merely to recover terminology/visual-family facts already captured here.
