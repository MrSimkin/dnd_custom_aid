## Export is distinct from Save

When structural edits are pending, Android does not force a save and does not silently discard the draft.

The user is warned:

`Exportar cambios sin guardar`

and must explicitly choose:

`Exportar sin guardar`.

The export aggregate is a pure projection of the current editor state and does not call the repository save flow.

The projection includes the current drafts for:

- core character sheet fields;
- combat entries/damage;
- equipment/currencies/inventory usage;
- background;
- traits and trait provenance;
- canonical race/background identities;
- spell sources/spells/spellcasting profiles;
- notes/cards;
- proficiencies;
- class options/forms/companions.

If required numeric draft fields are blank, the confirmation states that they are projected as 0 only for that export, matching the editor's existing draft-normalization behavior.

## Save behavior

Save uses Android:

`ActivityResultContracts.CreateDocument("application/pdf")`.

Flow:

1. generate PDF locally;
2. stage it under private app cache;
3. let the user select/create the destination document;
4. copy the generated bytes to the returned document URI;
5. delete the staged Save file.

A staged path and renderer notices survive normal Activity state restoration; the transient busy flag deliberately does not, preventing a process recreation from leaving the UI permanently stuck in "Generando".

## Share behavior

Share uses:

- a PDF staged under private app cache;
- a non-exported `androidx.core.content.FileProvider`;
- temporary URI read permission;
- `Intent.ACTION_SEND`;
- the Android chooser.

The FileProvider exposes only the bounded `pc-sheet-pdf/` cache subtree.

No public file path or network upload is introduced.

## Portrait behavior

The Android delivery service resolves locally available portrait bytes from:

- `content:` URIs;
- `file:` URIs;
- direct local file paths.

If a portrait ref is not locally available, the existing shared planner/renderer notice and blank-frame behavior remain authoritative.

## Current Snapshot behavior

Android currently has one canonical local PC aggregate, not a second independently durable Current Snapshot aggregate.

Therefore this package does not invent another PC model.

If Current Snapshot is requested without a separate source, the existing shared planner:

- falls back to Permanent;
- emits `CURRENT_SNAPSHOT_UNAVAILABLE`;
- surfaces that notice to the user.

This is an explicit residual capability gap, not a hidden claim that two local state aggregates already exist.
