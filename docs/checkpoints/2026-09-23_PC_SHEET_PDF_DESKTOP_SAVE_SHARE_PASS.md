## Implementation

Desktop PC Manager now exposes the D-0074 export-time choices:

- visual family:
  - Fantasy Sheet;
  - Custom v1;
  - Custom v2 - per Attribute;
  - Custom v2 - per Ability;
- Permanent vs Current Snapshot request;
- custom-stat presentation mode when custom statistics exist;
- portrait Crop-to-fill vs Fit-entire-image when a portrait ref exists;
- optional Spellbook descriptions.

Delivery behavior:

### Save

- user selects a local path through the Desktop file chooser;
- generated bytes are written via a temporary sibling file and atomically replaced when the platform supports atomic move;
- no server/provider/Internet dependency is introduced.

### Share

Desktop has no portable Android-style native share-sheet API.

The bounded Desktop implementation therefore:

1. generates the exact same PDF byte stream;
2. writes it to a temporary local PDF;
3. places that PDF on the system clipboard as a file-list transfer;
4. tells the user to paste the file into a compatible mail/chat/file destination.

This is local/offline and does not alter PDF content.

## Current-state and portrait behavior

Desktop PC Manager currently has one durable local canonical PC aggregate. It supplies that as the Permanent export source.

If Current Snapshot is requested and no separate current snapshot source exists, the already-approved planner falls back to Permanent and emits its existing notice. The UI surfaces that notice rather than pretending a distinct snapshot exists.

For portraits, the delivery service recognizes locally accessible file/path refs when available. If the portrait ref is not available locally, the existing planner/renderer contract continues with a blank portrait area plus its existing notice.

No network fetch is added merely to render a PDF.

## Implementation-parity regression guard

New test:

`DesktopPcSheetExportServiceTest.saveAndShareDeliveryUseTheExactFrozenProductionRendererOutput`

For the same canonical export request it:

1. generates a PDF through `DesktopPcSheetExportService`;
2. generates a PDF by directly invoking `DesktopPcSheetWholeDraftRenderer`;
3. requires identical render plan;
4. requires identical page count;
5. requires identical extracted text;
6. rasterizes every page at 72 DPI and requires pixel-for-pixel equality;
7. verifies Save writes the generated bytes unchanged;
8. verifies the Share staging file contains the generated bytes unchanged.

This closes the specific risk that Desktop Save/Share could silently use a second renderer or change the approved design during invocation.
